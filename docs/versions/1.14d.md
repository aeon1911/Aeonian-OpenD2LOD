# Inventário da instalação 1.14d

> **Fonte:** instaladores oficiais da Blizzard fornecidos pelo usuário
> (`D2-1.14b-Installer-enUS` e `D2LOD-1.14b-Installer-enUS` + patches
> `D2Patch_114d.exe`/`LODPatch_114d.exe`). O usuário possui as chaves
> originais; nenhum arquivo da Blizzard é versionado neste repositório.
>
> **Método:** os arquivos foram extraídos dos "Installer Tome.mpq" com o
> extrator do projeto e os patches 1.14d foram lidos do overlay MPQ interno
> (`PrePatch.exe` + 24 bytes de cabeçalho). Não foi necessário executar o
> instalador Windows nem usar serial no processo.

## Onde está

- Instalação reconstruída (fora do repo):
  `/run/media/system/STEAM/Projetos/d2-114d`
- Base 1.14b extraída:
  `/run/media/system/STEAM/Projetos/d2-114b`
- Overlay de dados 1.14d: `d2-114d/data/` (1226 arquivos, ~18 MB)
- `Game.exe` final: 1.14d, sem DLLs (ver abaixo)

## `Game.exe` 1.14d

- PE32 i386, GUI, **3.618.792 bytes** (3,5 MB).
- `ImageBase = 0x00400000`; entry point `0x00282985`.
- Seções: `.text` `0x2CA5A1` (~2,9 MB), `.rdata` `0x38A10`, `.data` `0x48000`,
  `.rsrc` `0x1988`, `.reloc` `0x224FE`.
- Versão de recurso: **1.14.3.71**.
- **Monolítico:** imports apenas de sistema/terceiros
  (`KERNEL32`, `USER32`, `GDI32`, `ADVAPI32`, `WINMM`, `WS2_32`, `DSOUND`,
  `DDRAW`, `ole32`, `SHELL32`, `PSAPI`, `VERSION`, `WINTRUST`, `CRYPT32`,
  `IMM32`, `binkw32`, `smackw32`, `ijl11`). **Não importa** Storm.dll,
  Fog.dll, D2Common.dll, D2Client.dll etc.
- 24 exports nomeados (C++ mangled), incluindo `BNGatewayAccess` e
  `SErrSetBlizzardErrorFunction`; não há exports de SFile/SStr/SMem como na
  1.13c.
- O patch 1.14d **remove as DLLs** e substitui o `Game.exe`; os módulos
  D2Client/D2Common/D2Game/Storm/Fog/D2Win/D2CMP/D2Lang/D2Sound/D2Gfx foram
  linkados estaticamente no executável. As strings `__FILE__`
  (`D2Client/Engine.h`, `D2Common/CmnItems.h`, `D2Game/Quests/*.cpp`,
  `Storm/Source/SFile.cpp`, `Fog/Src/...`) confirmam a composição.
- O `Game.exe` vem embrulhado num header de 24 bytes do PrePatch; o arquivo
  instalado é o PE a partir do offset 24. O hash acima é do PE já sem wrapper.

## Dados 1.14d

- `patch.lst` base: 1153 arquivos; `patch.lst` LoD: 215 arquivos.
- Overlay final em `d2-114d/data/`: 1226 arquivos (inclui `.txt`, `.bin`,
  `.dc6`, `.dcc`, `.ds1`, `.wav`), aplicado sobre os MPQs 1.14b.
- Os MPQs base (`d2data`, `d2exp`, `d2char`, etc.) são os de 1.14b; o patch
  1.14d é um overlay de dados + novo executável. Isso é compatível com a
  estratégia de mods por override do nosso motor.

## Consequências para o projeto

1. **Não há ABI de ordinais para copiar na 1.14d.** O alvo de análise passa a
   ser um único `Game.exe`; as specs 1.13c de Storm/Fog/D2Common são
   **hipóteses comportamentais**, não contratos de ABI.
2. **Adaptadores por ordinal não são necessários** para 1.14d; podemos
   implementar o comportamento direto no nosso motor.
3. O trabalho de formatos (MPQ/PAL/DC6/DS1/DT1/DCC) e do engine continua
   válido; os assets vêm de `d2data.mpq` + overlay `data/`.
4. Precisamos de um **resolvedor de assets com override** (diretório de
   patch/mods > MPQs), que também é a base do sistema de modding.
5. Para análise: importar `Game.exe` no Ghidra (ImageBase `0x00400000`),
   mapear funções por strings/call graph e comparar com as funções 1.13c
   equivalentes. Não usar offsets de 1.13c como se fossem 1.14d.

## Como reproduzir a instalação

Fora do repositório:

1. Extrair `PC-100` (D2 base) e `Common` do `Installer Tome.mpq` do
   instalador 1.14b.
2. Extrair `PC-100x` e `Common` do Tome do LoD 1.14b; copiar por cima.
3. Extrair o overlay MPQ de `D2Patch_114d.exe`/`LODPatch_114d.exe`
   (offset 0x29000) e aplicar `patch.lst` em `data/`.
4. Substituir `Game.exe` pelo PE do patch (remover os 24 bytes de wrapper) e
   remover as DLLs antigas.
5. O resultado é `d2-114d/`, a instalação de teste (ver `HANDOFF.md`).
